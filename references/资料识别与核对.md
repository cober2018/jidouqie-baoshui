# 资料识别与核对

## 1. 识别资料

文件名只做线索。用 `dump_file.py` 读取表格和文本 PDF。图片或扫描件需人工查看或复核提取结果。先确认文件里的企业和期间，处理前检查表头、金额正负和遗漏行。

| 资料 | 识别和复核 |
|---|---|
| 上期财务报表 | 确认主体和所属期，检查三张表的完整性、资产两侧是否平衡。脚本可读取兼容的 `.xls` 或文本 PDF |
| 上年年报 | 确认是上一完整年度，取利润表和现金流量表的本年累计金额作年报对比 |
| 发票导出表 | `.xlsx` 中有发票基础、汇总或明细工作表，核对开票日期、销方识别号、购方识别号、金额和状态 |
| 电子发票 PDF | 确认可提取发票号码、日期、购方和销方识别号、价税合计。复核脚本未识别的票据及红字票 |
| 银行流水 | 按账户和币种确认覆盖范围。脚本读取兼容的 `.xls`、`.xlsx` 和 `.csv`，检查日期、收支、余额和对方名称；其他格式需人工整理 |
| 工资社保 | 检查费用所属月、实发或实缴日、个人和单位承担金额 |
| 税费 | 核对税种、所属期、申报金额、缴款日期和金额。单凭申报成功页面只能证明申报 |
| 其他凭证 | 合同、回单、报销单和付款凭据用于确认用途、收付款时点和是否垫付 |

对重复来源做去重，保留原始凭证。发票脚本按发票号码匹配，表格与 PDF 的号码或金额不一致时检查原件。流水出现同金额交易不必然重复；对照日期、交易流水号和凭证。水印或异常版式可能导致 PDF 漏行，核对合计与行次。

## 2. 缺项和估算

| 缺项 | 处理 |
|---|---|
| 上期数据或新开业期初信息 | 取得批准使用的原始资料。第一期能否用零期初，需要核对设立、实缴、资产和往来记录 |
| 全量发票或无票业务信息 | 确认本期收入和支出的完整性，核实发票状态后再汇总 |
| 全部或部分银行流水 | 写清可对账的账户和日期。向用户说明未覆盖的收款、付款及往来需要复核 |
| 工资或社保资料 | 核对是否确有该类业务，补齐能拆出单位和个人承担数的凭证 |
| 申报或缴款资料 | 分开记录应纳、已申报和已缴金额；暂估时写清前提与未核对事项 |
| 上年年报 | 年报需要对比数据。确认上年确无业务或余额后，按实际情况提供零值，保持草稿直到核对完成 |

## 3. 请用户核对

合并成一条消息，简述已收到的资料、实质缺项和未匹配的交易。列最小必要信息，可用日期、金额、对方简称识别。询问业务事实，例如「有一笔收款找不到发票，这是预收款、已完成订单的货款，还是其他款项？」确认后在底稿写明依据。

## 4. 归档

在用户的私有资料目录按公司和期间存放。按需要把原始凭证分为上期报表、开出的发票、收到的发票、银行流水、工资社保、税费和其他凭证。不属于该公司或期间的资料注明原因，并按原有存放方式处理，避免混入公司归档。底稿的来源字段使用能在私有目录内追溯的文件名或编号。
