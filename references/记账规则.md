# 记账和底稿格式

结合本期凭证、上期余额和公司已经核实的口径编制分录。下文列出脚本支持的写法及常见业务的核对方法。会计口径可参照财政部 [《小企业会计准则》](https://kjs.mof.gov.cn/zhengcefabu/201111/P020111118325852319878.pdf) 和 [会计科目、主要账务处理和财务报表附录](https://kjs.mof.gov.cn/zhengcefabu/201111/P020111118325852734144.pdf)。

## 1. 总原则

- 确认收入、成本和费用时区分业务发生、开票和实际收付。未结清的款项按业务性质挂往来。
- 区分发票价税合计和本期应确认的金额。购买资产、预付款或购入存货按性质处理，收到发票不必然意味着本期确认费用。
- 每笔分录可追溯到凭证或用户确认。可以按月份和科目汇总重复性质的小额凭证，底稿应能追溯构成并与汇总表勾稽。
- 计算和制表依赖分录完整性和凭证判断。脚本发现报表平衡只说明数值校验通过。

## 2. 可用科目

`ledger.py` 用科目名称映射报表行次。格式为「一级科目」或「一级科目-明细」。支持的名称与行次以 [脚本的 `ACCOUNTS` 和 `SUBLINES`](../scripts/ledger.py) 为准。部分常用写法如下。

| 类别 | 常用写法 |
|---|---|
| 现金和往来 | 银行存款、库存现金、应收账款、预付账款、其他应收款、应付账款、预收账款、其他应付款 |
| 存货和其他资产 | 库存商品、原材料、固定资产、累计折旧、无形资产、累计摊销 |
| 其他负债和所有者权益 | 应付职工薪酬、应交税费、短期借款、长期借款、实收资本、资本公积 |
| 收入和费用 | 主营业务收入、营业成本、税金及附加、销售费用、管理费用、财务费用、所得税费用 |

部分明细关键词有专门的行次，例如 `税金及附加-印花税`、`销售费用-广告费`、`管理费用-研发`、`财务费用-利息支出`。脚本自动把本期净利润结转到未分配利润，分录中记录实际发生的利润分配等事项，并说明其对勾稽的影响。

## 3. 发票与跨期事项

- `invoices.py` 将开出和收到的票按发票号归并，并给出所属期、红字和排除项。复核全量发票、单张 PDF、未开票交易和脚本漏识别的记录。
- 开票与收入满足确认条件时，按业务和适用税务处理确认收入、应交税费与应收款。已经收款的对照流水结清应收款。预收、跨期和无票交易结合业务实质处理。
- 核对收到票据的商品或服务类别、实际付款人和用途。直接用于交付的支出、期间费用、存货、固定资产、预付款按业务分别处理。员工或股东垫付以报销单和付款记录为准。
- 红字票须对照对应原票和已入账期间。检查是全额还是部分冲销，有无重复开票、退款或再次付款。原票已在上期入账的，核对本期应冲减的账项。款项已经支付又待退款或换票时，保留真实收付记录和往来。

## 4. 工资、社保和个税

按员工薪酬所属期和实际支付日期分别记录。核对工资表、银行代发、社保缴款及扣缴资料。工资和单位承担的社保部分按相应费用计入应付职工薪酬；代扣的个人承担部分和个税按公司口径核对，缴付及发薪按真实付款冲减对应负债。差额查明是否含补缴、滞纳金、代扣或跨期情况。

## 5. 税费

按税种分别核对应纳、已申报和已缴金额。应交税费余额、实际缴款与所得税费用、税金及附加可对应不同期间。核对纳税主体、计税依据、政策适用条件、所属期和相关申报记录。

- **增值税及附加**。核对销售额和纳税义务发生期间、计税方式、发票及无票业务、减免资格和适用征收率。附加税费按适用计税依据和主管地政策确认。
- **印花税**。检查合同、应税凭证或账簿的类别及金额，以确认申报为准。仅有发票时，先核实纳税义务和计税依据。
- **企业所得税**。核对利润、税务调整、减免资格和可结转亏损。可弥补亏损以经核实的所得税申报记录等为依据。
- **个人所得税**。工资或劳务扣缴按已确认的扣缴资料核对，并与发薪、支付和实际缴税分开记。

不同期间和业务的政策可能不同。参考 [国家税务总局政策法规库](https://fgk.chinatax.gov.cn/)，用该笔业务适用的政策和主管税务机关口径。仅能估算时，在草稿中写明依据和待补资料。

## 6. 银行流水和缺项

- `bank.py` 按摘要关键词、发票号或对方加金额寻找候选匹配。发票金额、流水或上期往来金额相同只能提供线索，核查分笔、合并收款、退款、内部划转和重复导出。
- 按账户复核期初、期末和区间。单个账户的余额不能直接拿来核对全部货币资金。多账户、现金和其他货币资金需要汇总核对。
- 遗漏流水时，逐笔标记有凭证支持的收付和未核实的款项。用户需要估算草稿时，列出每项假设和核对范围，保留未结事项。没有付款证据时不能由开票、发薪月份或缴税习惯认定已付款。

## 7. 其他常见业务

| 业务 | 核对和处理 |
|---|---|
| 客户预付款 | 先核对合同及履约，确属预收款时示例为借银行存款、贷预收账款 |
| 股东转入资金 | 核实是借款还是出资。根据真实性质和凭证使用其他应付款、实收资本等科目 |
| 股东或员工代付 | 按报销和付款凭证确认公司业务及垫付人，核实之后清偿 |
| 购买设备 | 核对使用期限、成本、适用的资产确认及折旧口径 |
| 银行手续费、结息 | 按银行记录分类，用途不清的交易先核对 |
| 公司账户之间转账 | 双边核对，现金内部流转在现金流量表不产生对外收付款 |

## 8. 现金流量表

`ledger.py` 依据现金类科目的对方科目给出行次。多种用途混在一笔分录时，脚本默认根据金额最大的对方科目分类。复核分类，必要时按真实现金用途拆分或用 `"现金流": 行次` 指定。其中 1–6、8–12、14–18 是可填的明细行次。单纯现金内部划转不产生净现金流量。

## 9. 上期没有现金流量表时怎么处理

优先取得上期报表或根据实际现金收付记录复原上期本年累计。对照银行流水、现金记录、报表和已确认的往来变化。年初到上期末的现金差额可作合计核验，无法独立证明各行实际金额。资料只支持估算时，写明草稿假设和缺项，避免把未核实差额归入任意一行。

若上期没有现金流量表，且本期并非从 1 月 1 日开始，`ledger.py` 需要 `上期现金流量表本年累计`。将核对过的明细行次填入该对象。开始新的会计年度时，脚本用上一年度期末作年初，本年累计从本期开始。

## 10. 本期工作.json 字段

以下虚构示例只演示字段。名称和标识符用于本地测试。

```json
{
  "公司": {"名称": "示例主体（虚构）", "税号": "DEMO-ONLY"},
  "所属期": {"起": "2030-01-01", "止": "2030-03-31", "报表": "季报"},
  "上期": {
    "资产负债表": {
      "期末": {"1": 1000, "30": 1000, "48": 1000, "53": 1000},
      "年初": {}
    }
  },
  "分录": [
    {
      "日期": "2030-01-04",
      "摘要": "收到出资款",
      "借": "银行存款",
      "贷": "实收资本",
      "金额": 2000,
      "来源": "合成凭证-A"
    },
    {
      "日期": "2030-01-05",
      "摘要": "支付银行手续费",
      "借": [["财务费用-手续费", 10]],
      "贷": [["银行存款", 10]],
      "来源": "合成凭证-B"
    }
  ]
}
```

- `上期` 接受 `parse_prior_report.py` 生成的 JSON 对象或文件路径。实际使用应保存完整的上期数据。
- `借`、`贷` 可以都是科目名称，并用 `金额` 提供同一金额，也可以使用若干 `[科目, 金额]`。
- `上期现金流量表本年累计` 以行次为键、金额为值，用于本年度非首期且上期未附现金流量表的情况。
- 编年报时，`上年金额` 的 `利润表`、`现金流量表` 以行次为键，来自上年全年金额；确认实际为零后才填零。
